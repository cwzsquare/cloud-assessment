## 1. 先确认靶场健康

PVE 侧确认 VM、快照、thin-pool、WG 出口：

```bash
ssh cloudnative-env 'qm list'
ssh cloudnative-env 'for id in 111 102 103; do qm listsnapshot $id; done'
ssh cloudnative-env 'pvesm status'
ssh cloudnative-env 'curl -4 --interface cnsec-lab https://api.ipify.org'
```

Kubernetes 侧确认 control-plane 和节点：

```bash
ssh cloudnative-env 'ssh -i /root/.ssh/agent_lab -o UserKnownHostsFile=/dev/null -o StrictHostKeyChecking=no agent@10.20.0.11 "sudo KUBECONFIG=/etc/kubernetes/admin.conf kubectl get nodes -o wide"'
ssh cloudnative-env 'ssh -i /root/.ssh/agent_lab -o UserKnownHostsFile=/dev/null -o StrictHostKeyChecking=no agent@10.20.0.11 "sudo KUBECONFIG=/etc/kubernetes/admin.conf kubectl get pods -A"'
```

你应该至少看到：

- `k8s-cp-1`、`k8s-worker-1`、`k8s-worker-2` 都是 `Ready`
- `falco`、`calico-node`、`kube-proxy` 都已恢复

## 2. CLI 全流程

### 2.1 运行一次当前 live 扫描

```bash
PYTHONPATH=apps/api python3 -m cloudnative_security.cli \
  --pve-ssh cloudnative-env \
  --profile all_tools_demo \
  --task-id pve-good-live-20260630b \
  --output artifacts/reports/pve-good-live-20260630b.json \
  --markdown-output artifacts/reports/pve-good-live-20260630b.md \
  --html-output artifacts/reports/pve-good-live-20260630b.html \
  --sqlite artifacts/assessment.sqlite3
```

这条命令会走这条路径：

1. [cli.py](/root/cloud-assessment/apps/api/cloudnative_security/cli.py:14) 解析参数并创建 `AssessmentRequest`
2. [adapters.py](/root/cloud-assessment/apps/api/cloudnative_security/adapters.py:131) 进入 `CloudNativeAdapter`
3. [collector.py](/root/cloud-assessment/apps/api/cloudnative_security/collector.py:431) 通过 `PVE -> control-plane VM` 采集 Kubernetes、control-plane manifest、auth.log
4. [rules.py](/root/cloud-assessment/apps/api/cloudnative_security/rules.py:1732) 执行云原生三级模块对应规则
5. [orchestrator.py](/root/cloud-assessment/apps/api/cloudnative_security/orchestrator.py:240) 做归一化、数据质量、评分和报告
6. 输出 `json/md/html/sqlite`

## 3. Web 全流程

当前有两种启动方式。

### 3.1 用 Docker Compose 启动

```bash
docker compose up
```

默认会启动：

- 服务定义：[docker-compose.yml](/root/cloud-assessment/docker-compose.yml:1)
- API/静态前端入口：[cli.py](/root/cloud-assessment/apps/api/cloudnative_security/cli.py:14)
- 监听地址：`http://127.0.0.1:18080/`

### 3.2 不用 Docker，直接本地起服务

```bash
PYTHONPATH=apps/api python3 -m cloudnative_security.cli \
  --serve \
  --host 127.0.0.1 \
  --port 18080 \
  --sqlite artifacts/assessment.sqlite3
```

服务端入口在 [server.py](/root/cloud-assessment/apps/api/cloudnative_security/server.py:277)。

## 4. Web 页面怎么用

打开：

```text
http://127.0.0.1:18080/
```

前端页面结构在 [index.html](/root/cloud-assessment/apps/web/static/index.html:1)，交互逻辑在 [app.js](/root/cloud-assessment/apps/web/static/app.js:1)。

推荐按这个顺序看：

1. `总览`
   看总分、结论、证据覆盖率、Severity/Status 分布、整改优先级。
2. `云原生详情`
   看 15 个三级模块对应检查点的状态、得分、RBAC 权限矩阵。
3. `Findings`
   按 `checkpoint/severity/status/namespace/kind/keyword` 过滤，点具体行看证据和整改建议。
4. `报告预览`
   直接查看 JSON/Markdown/HTML 报告导出链接。
5. `目标/任务`
   录入目标并创建新的 live assessment 任务。

## 5. 在 Web 里重新跑一次评估

如果你想从页面触发一次新的靶场扫描：

1. 打开 `目标/任务`
2. 在“目标导入”里填：
   - `目标名称`：`PVE K8s 正向靶场`
   - `连接模式`：`PVE SSH`
   - `PVE SSH alias`：`cloudnative-env`
   - `control-plane IP`：`10.20.0.11`
   - `SSH key`：`/root/.ssh/agent_lab`
   - `SSH user`：`agent`
3. 点 `保存目标`
4. 在“创建评估任务”里选择该目标
5. `profile` 选 `all_tools_demo`
6. `task id` 例如填 `pve-good-web-run-20260630`
7. 点 `创建并运行`

这个流程最终调用的是：

- `POST /api/targets`
- `POST /api/assessments`

对应实现都在 [server.py](/root/cloud-assessment/apps/api/cloudnative_security/server.py:93)。

## 8. 当前这套正向样例的已知残留

这套样例今天能完整跑通，但不是满分基线，当前还会稳定暴露这些问题：

- `CN-6`
  - `orders-db` 没有 `HPA/PDB`
- `CN-30`
  - 仍能识别到异常登录事件
- `CN-36`
  - `PV` 仍是实验性的 `hostPath`
- `CN-37`
  - 缺少绑定到 `orders-db` 的备份/快照证据
- `CN-38`
  - 真实 registry API 仍未接入，只能做原型级供应链评估

所以这套样例适合做：

- 工具链路演示
- 三级模块能力演示
- CLI/Web/API 流程演示
- 正向样例基础上的整改演示

不适合直接当作“已经全部收口的终验金样例”。
